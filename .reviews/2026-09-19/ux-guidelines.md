# MakeIt member app — interface guidelines & accessibility review

Reviewed in Playwright MCP against dev server http://localhost:3002 (demo mode, invite MUNK-01), logged in as @Munk.
Light "Kalk" theme unless noted. Checked at 390×844 first, 1440×900 spot-check on dashboard.

| Surface | Severity | Finding | Evidence | Suggested fix |
|---|---|---|---|---|
| /dashboard (also reproduced on /mind) | important | Onboarding "tour" dialog (`role="dialog" aria-modal="true"`) does not trap focus and does not close on Escape. Tabbing from body lands on the "Beskeder" header link, which sits behind the visually-blocking modal. | `browser_evaluate` on `document.activeElement` after Tab from blurred body returned the `<a aria-label="Beskeder" href="/messages">`, `closest('[role="dialog"]')` = false. Escape keypress left `document.querySelector('[role="dialog"]')` truthy both on /dashboard and /mind (same shared component). Screenshot: `/Users/tomhedegaard/.playwright-mcp/shots/ux/dashboard-390-onboarding-modal-focus-leak.png` | Rebuild the tour dialog on the same modal primitive used for "Afslut session?" (Radix Dialog, which correctly traps focus and closes on Escape — verified working on /session/[id]). Add `onEscapeKeyDown`/focus trap. |
| /dashboard | minor | The tour dialog re-appears every time the member navigates back to /dashboard in the same session, even after "Spring over" (skip) was already used once. | Manually skipped tour, navigated to /mind and back to /dashboard; dialog reappeared with identical copy. | Persist "tour dismissed" in localStorage/user prefs so it only shows once (or once per feature, not once per page load). |
| /dashboard — "Sammenhængene" cards | important | Secondary action buttons are far below any touch-target minimum: "Skjul" 37×15px, "I morgen" 59×15px (×3 repeats), "Sig mere om …" links 31px tall, "Se uge →"/"Se feed →" 73×17 / 81×17px. | `getBoundingClientRect()` sweep of buttons/links in viewport, values in px above. | Raise min-height to 44px (or at minimum 24px per WCAG 2.5.8) with adequate padding; these are dense clusters of small tap targets right next to each other. |
| /train/exercises | important | Category filter chips ("Alle", "Ben", "Helkrop", "Push", "Skuldre", "Pull", "Core", "Arme") — the primary way to browse this page on mobile — are 30px tall, below the 44px touch-target guideline. | `getBoundingClientRect()`: e.g. "Ben" 53×30, "Helkrop" 88×30, "Push" 62×30. | Increase chip height to ≥44px; good news is these are already real `<a>` links reflecting state via `?category=` query params (correct URL-as-state pattern) — just needs bigger hit area. |
| /train (from dashboard/nav "Træn" would be expected here) | minor | `/train` 404s ("This page could not be found"). The working route for training content is `/coaching`; `/train/exercises` and `/train/exercises/[slug]` do work. | `browser_navigate` to `/train` → HTTP 404, 1 console error. | Either add a redirect from `/train` → `/coaching`, or confirm this is intentional IA and document it; a stray 404 under a live nav-adjacent path is easy to hit by URL guessing/bookmarking. |
| /train/exercises/back-squat (exercise detail) | important | Zero `<h2>`/`<h3>` on the page except the `<h1>`. All content sections — "Sådan udfører du den", "Muskler involveret", "Typiske fejl", "Setup", "Progression", "Regression" — are plain `<div>`s, not headings. | `document.querySelectorAll('h2')` → `[]` on a content-dense page; snapshot confirms section labels render as `generic`, not `heading`. | Promote each section label to `<h2>` (or `<h3>` under the exercise name) so screen-reader users can navigate by heading, per "Headings hierarchical" guideline. |
| /nutrition | minor | Feed's "today" meal-card action buttons ("Vis opskrift", "Byt", "Log") all have identical, non-unique accessible names (just "Byt", "Log", "Vis opskrift") across 3 meal cards, while the near-identical "Resten af ugen" weekly rows correctly build unique labels like `"Byt Spinatomelet med feta"`. | Snapshot comparison: today's cards → `button "Byt"` ×3 identical; week rows → `button "Byt Spinatomelet med feta"`. | Apply the same pattern used in "Resten af ugen" to today's meal-card buttons, e.g. `aria-label="Byt {mealName}"`. |
| /nutrition, /community, app-wide | minor | Systemic button height of 36px (Log, Byt, Vis opskrift, Regenerér ugeplan, Indkøbsliste, Indstillinger…) and 28px (crew feed reactions: "+84 Reps", "12 Kommentarer", "Del") — below the 44px guideline though still above WCAG AA's 24px floor. | `getBoundingClientRect()` sweep on /nutrition and /community; ~30 buttons returned at 28–36px height. | Design-system-level fix: bump the default/`sm` button size token toward 40–44px, especially for primary actions like "Log" and "Regenerér ugeplan". |
| /nutrition/shopping | minor | Checklist toggle buttons correctly expose `aria-pressed` (verified true/false on click) — good — but the running progress counter ("1 / 54") that updates on each check is not inside an `aria-live` region, so screen-reader users get no spoken progress feedback while shopping. | `closest('[aria-live]')` = false on the counter node after toggling one item. | Wrap the "`n` / 54 varer" counter in `aria-live="polite"` (or add a visually-hidden live announcement on toggle). |
| /hrv, /hrv/trends | minor | Document `<title>` stays the generic "MakeIt // HQ" instead of a descriptive title, inconsistent with other sections (e.g. Nutrition = "Mad · MakeIt", exercises = "Back Squat · Train · MakeIt // HQ"). | `document.title` = "MakeIt // HQ" on both /hrv and /hrv/trends. | Set page-specific `<title>`, e.g. "HRV · MakeIt", "Forløb · HRV · MakeIt". |
| /hrv/trends | — (positive, no action needed) | Chart is exemplary: `<img>` with a full descriptive alt text plus a visually-hidden `<table>` fallback with proper `<caption>`/`<th>` giving every data point. Noted for contrast with /profile below. | Snapshot shows `img "HRV-trend Daglig HRV (RMSSD)…"` immediately followed by a real `<table>` with 21 rows of date/RMSSD data. | None — use as the reference pattern for other charts (see /profile finding). |
| /profile | minor | The "Score-udvikling over tid" form-check sparkline is a bare `<svg aria-hidden="true">` inside a `<div aria-label="Score-udvikling over tid">` — no data table fallback like the HRV chart has. Low risk here since the same numbers (79/100, snit 82, -5 siden første) are already printed as text nearby, but it's an inconsistent pattern vs. /hrv/trends. | `outerHTML` of the labelled wrapper shows only a decorative `<path>`, no table sibling. | Optional: add the same hidden-table pattern used on /hrv/trends for consistency, or leave as decorative since the numbers are already textual. |
| /settings | important | "Slet min konto" (delete account) — a fully destructive, irreversible action — is confirmed via the browser's native `window.prompt()` ("Skriv \"SLET MIN KONTO\" for at bekræfte") rather than an in-app dialog. | `browser_click` on the button surfaced a native "prompt" modal state (not a `role="dialog"` in the page); dismissed via `browser_handle_dialog({accept:false})` without deleting anything. | Replace with an in-app confirm dialog (the same Radix pattern already used for "Afslut session?"), keeping the "type to confirm" friction but making it stylable, themeable, and consistent with the rest of the app's a11y patterns. |
| /billing | blocker | Both plan prices render as literal, unreplaced template placeholders — "[XX] kr / md" for Crew-medlemskab and "[ZZ] kr / md" for 1:1 Coaching — so a member cannot see what they would be charged before starting checkout. | Snapshot: `generic "[XX] kr / md"` / `generic "[ZZ] kr / md"`. Screenshot: `/Users/tomhedegaard/.playwright-mcp/shots/ux/billing-390-placeholder-price.png` | Wire the real price into this template string (or hide the row until pricing is configured) before this ships; a member cannot make an informed purchase decision with a visible `[XX]` token. |
| /onboarding | important | The "days per week" selector (3/4/5 dage / uge) uses plain `<button>`s with zero selection-state semantics — no `aria-pressed`, `aria-checked`, or `aria-selected` — while the adjacent Mål/Niveau/Udstyr questions correctly use native `<input type="radio">`. After clicking "4 dage / uge" all three ARIA state attributes remained `null`; only a CSS class changed. | `getAttribute('aria-pressed'/'aria-checked'/'aria-selected')` all `null` post-click; class changed to include selected styling only. Screenshot: `/Users/tomhedegaard/.playwright-mcp/shots/ux/onboarding-390-frequency-no-state.png` | Convert to a real radio group (native inputs, as used elsewhere on the same page) or add `aria-pressed`/`role="radio"` + `aria-checked` so screen-reader/keyboard users can perceive the current selection. |
| /onboarding | minor | The three radio question groups (Mål, Niveau, Udstyr) have no `role="radiogroup"` wrapper or `<fieldset>`/`<legend>` — grouping is conveyed only by a preceding `<h2>`, not formally associated to the radios. | `document.querySelectorAll('[role=radiogroup], fieldset').length` = 0 on a page with 3 distinct radio questions. | Wrap each question's radio set in `<fieldset><legend>` or add `role="radiogroup" aria-labelledby`. |
| Live session /session/[id] (dark "Nat" theme) | — (positive, no action needed) | Core logging flow is solid: `color-scheme: dark` set correctly, weight/reps use native numeric inputs (`inputmode="decimal"/"numeric"`, 32px font — well clear of the iOS 16px zoom threshold) with 56–87px stepper buttons, RPE uses a real `radiogroup`, and "Afslut session?" is a correctly-built Radix dialog that traps focus and closes on Escape (confirmed). | Directly contrasts with the broken onboarding-tour dialog and the native-`prompt()` delete-account flow above — this is the pattern the rest of the app should follow. | None — reference implementation. |
| Live session /session/[id] | minor | "Hvil" (rest) button is 63×36px and "Afslut session" is 40×40px — both below the 44px guideline, consistent with the app-wide button-height pattern. | `getBoundingClientRect()`: Hvil 63×36, Afslut session 40×40. | Same fix as the app-wide button-height finding above. |
| All surfaces checked | — (positive) | No horizontal scroll on any surface at 390px (`document.documentElement.scrollWidth` ≤ `window.innerWidth` everywhere tested), no `transition: all` found, no console errors on any route except the expected 404 on `/train`, one `<h1>` per page everywhere except the exercise-detail heading gap noted above. | Measured via `browser_evaluate` + `browser_console_messages` on every surface in scope. | None. |

## Severity counts
- Blocker: 1 (billing placeholder pricing)
- Important: 7 (onboarding-tour focus trap/Escape; dashboard small touch targets; exercises category-chip touch targets; exercise-detail missing headings; native-prompt account deletion; onboarding frequency selector missing ARIA state)
- Minor: 9 (tour re-appearing; /train 404; nutrition button-label inconsistency; app-wide 28–36px buttons; shopping-list progress not live; HRV/trends page `<title>`; profile sparkline no table fallback; onboarding radiogroup grouping; session Hvil/Afslut button height)
